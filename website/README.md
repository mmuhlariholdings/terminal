# Terminal 1 website

The marketing and project page for Terminal 1. A hand-written static site: HTML, CSS and vanilla JavaScript, with
no build step and no framework.

```
website/
  public/                 everything that gets published
    index.html            the page
    404.html              self-contained "not found" page (GitHub Pages serves it for any missing path)
    assets/css/site.css   all styles
    assets/js/site.js     all behaviour (menu, terminal demo, 3D model loader)
    assets/fonts/         IBM Plex Mono and Sans, self-hosted woff2, with OFL.txt
    assets/images/        concept renders (WebP + JPEG), og-image, favicon
    assets/models/        terminal-1.glb goes here once it is exported from Onshape
```

## Run locally

From the repository root:

```sh
python3 -m http.server -d website/public 8000
```

Then open <http://localhost:8000>. Use a server rather than opening the file directly: the 3D model check uses
`fetch`, which does not work from `file://` (the page falls back to the poster image).

## Things to know before editing

- **Repository URL.** It lives in one place: `REPO_URL` at the top of `assets/js/site.js`. Every link marked
  `data-repo="…"` in the HTML is built from it (the attribute value is the path appended to the URL). Without
  JavaScript those links fall back to the in-page FILES section.
- **Site URL.** `canonical`, `og:url` and `og:image` in `index.html` assume
  `https://mmuhlariholdings.github.io/terminal-1/`. Change them if the repo name or a custom domain changes.
- **Honesty rules.** Nothing is built yet. Every figure is an estimate or target, renders are labelled "Concept
  render, AI-generated" in their captions, and the BUGS section (the vibe-coded disclosure) and footer line stay. Update numbers from `system/plan/interfaces.md`, which
  is the project's single source of truth.
- **Motion.** There are no scroll effects. The typing demo, the blinking cursor and the model auto-rotate switch off
  under `prefers-reduced-motion` (the demo then shows each session complete). Check both.
- **Old anchors.** Empty `<span class="alias">` elements keep the previous section links (`#screen`, `#inside`,
  `#specs`, `#open-source`, `#vibe-coded`, ...) working.

## Design language

The page is the device's manual page, set as a hardware datasheet. Keep it that way:

- **Structure.** Unix man-page skeleton: header line `TERMINAL-1(1) · Terminal 1 Manual · TERMINAL-1(1)`, then NAME,
  SYNOPSIS, DESCRIPTION, DISPLAY, KEYBOARD, HARDWARE, MODEL, SPECIFICATIONS, ROADMAP, BUGS, FILES, SEE ALSO, and the
  man-page footer line. Each section is a ruled row: index and name (`§05 HARDWARE`) in the left three columns,
  content in the right nine.
- **Type.** IBM Plex Mono for structure: headings, labels, navigation, numbers, specs, buttons. IBM Plex Sans for
  reading. One big type moment (the name in the hero); section statements (`.lede`) stay at about 34 px. Only the
  weights in `assets/fonts/` exist: Mono 400/500/600, Sans 400/500 and 400 italic. They are the Latin subset, so
  arrows and box-drawing characters fall back to the system monospace.
- **Colour.** Paper `#F2F0EA` and ink `#151513`. Device photographs, the screen and the keyboard sit on black plates.
  One signal colour, amber `#FFB000`, used sparingly: the block cursor, "we are here", focus rings, selection and
  active states. Never amber text on paper (too little contrast).
- **Surface.** 12-column grid, 1 px rules, square corners (2 px at most). No gradients, glows, shadows, blurs, glass,
  noise, pill buttons, emoji, icon sets or three-card feature grids. Buttons are bordered rectangles in mono.
- **Figures.** Every image is a numbered figure with a caption (`Fig. 4`). Concept renders always say
  "AI-generated". Diagrams are technical drawings: hairlines, numbered balloons, dimension lines. The exploded view in
  HARDWARE is static inline SVG generated by `website/tools/exploded_view.py` (isometric projection of the stack-up in
  `system/plan/interfaces.md`); if the stack changes, regenerate it rather than editing coordinates by hand.
- **Voice.** Plain, technical, a little dry. Short declaratives with real numbers and units. Mark every estimate. No
  "wherever you are", no "Get started", no statistics that are not specifications.
- **Checks.** Desktop at 1440 px; phone at 390 px with 16 px gutters and no horizontal scroll. The DISPLAY demo is
  sized with container query units so it always shows exactly 90 × 45 cells.

## The 3D model

The MODEL section uses Google's `<model-viewer>` **3.5.0** (pinned, loaded from jsDelivr only when a model
exists). To publish the model:

1. In Onshape, export the assembly as **glTF binary (.glb)**. Keep it small (aim for under 5 MB: simplify fillets
   and hide fasteners if needed).
2. Save it as `website/public/assets/models/terminal-1.glb`.
3. Optional: export again with **Exploded view spacing 12 mm** and **Show internal parts** ticked, saved as
   `website/public/assets/models/terminal-1-exploded.glb`: an **Exploded view** button then appears and swaps between them.
4. Colours: Onshape's glTF export writes sRGB colours as linear and sets no finish. `finishMaterials` in `site.js` corrects
   this on load, keyed on the `T1_C_*` colours in `hardware/enclosure/terminal-1.fs`; keep that table in step.

Until the file exists, the section shows the concept render with a "3D model coming with the first CAD export"
note. Do not commit test models.

## Images

Source renders live in `docs/media/concept-renders/`. Variants were made with `sips` and `cwebp`, for example:

```sh
sips -s format jpeg -s formatOptions 78 --resampleWidth 896 docs/media/concept-renders/carbon-back.jpg \
  --out website/public/assets/images/carbon-back-896.jpg
cwebp -q 76 website/public/assets/images/carbon-back-896.jpg -o website/public/assets/images/carbon-back-896.webp
```

`keyboard-detail-520.*` is a crop of `annotated-desk.jpg` that avoids its baked-in labels (not used on the page at
present; the keyboard is shown as a key-legend diagram). `og-image.jpg` (1200 × 630, the hero set as a man page) and
`apple-touch-icon.png` were rendered from HTML with headless Chrome. `favicon.svg` and the touch icon are the amber
block cursor.

## Deploy

`.github/workflows/website.yml` publishes `website/public` to **GitHub Pages** on every push to `main` that touches
`website/**` (or by running the workflow by hand). One-time setup in the repository: **Settings → Pages → Build and
deployment → Source: GitHub Actions**.
